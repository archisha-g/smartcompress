Capabilities

Built to solve the problem,
not just describe it.

Every component is purpose-built: monitoring, prioritisation, compression, metadata, and restoration — fully integrated.

📡

Real-time Disk Monitoring

Polls disk usage every 10 seconds via psutil. Triggers compression automatically when available space drops below a configurable threshold (default 85%).

⚖

Intelligent Prioritisation

Ranks candidate files by last-access time and size. Large files untouched for weeks are compressed first, maximising space recovered per cycle.

🔒

Lossless Compression

Gzip and Zlib are both supported. Every compressed file can be restored byte-for-byte to its original state — no data is ever discarded.

🗃

Metadata Preservation

Original file paths, access timestamps, and algorithm choice are persisted in a JSON store. Decompression restores files to their exact original locations.

⌨

Graphical Interface

A Tkinter-based GUI provides manual compress and decompress controls, a live compressed-file registry, and a real-time disk usage display.

📋

Structured Logging

All compression and decompression events are timestamped and written to a log file, providing full auditability of every system action.

Architecture

Four steps. Fully automatic.

SmartCompress FS runs as a self-managing loop. Once started, it requires no interaction unless you choose to intervene via the GUI.

01

Monitor

A background loop polls disk usage every 10 seconds via psutil.disk_usage(). The threshold defaults to 85% but is fully configurable.

02

Scan & Rank

When usage exceeds the threshold, candidate files are collected and sorted by last-access time and size. System files are automatically excluded.

03

Compress

Top-ranked files are compressed with Gzip or Zlib. The original file's access and modification timestamps are recorded before compression begins.

04

Store & Restore

Metadata is persisted to compression_metadata.json. Any compressed file can be restored to its exact original path and timestamp at any time.
